## 教学目标

读者完成课程后，应能从“哪一种变化正在制造成本”出发，划分职责与运行时边界，选择不过度的原则、模式和系统架构，并用测试、运行证据和评审说明设计为什么成立。

主线技术固定为 Node.js + TypeScript。React 只用于解释 UI 状态所有权和前后端契约；Python 不进入主线；C++、Qt 与 OpenGL 仅作少量迁移类比。

## 贯穿案例

课程持续演进同一个任务管理 API：

```text
外部 JSON
→ HTTP 适配
→ 应用用例
→ 任务规则
→ 持久化端口
→ 内存或数据库适配器
```

最终可运行示例保持为模块化单体，使用 Node.js 内置 HTTP、TypeScript、Vitest 和内存 Repository。SQLite、PostgreSQL、事件总线与微服务在正文中作为真实的下一步设计问题讲解，不强行加入演示工程。

## 每章验收标准

每章都必须包含：当前问题、短 TypeScript 示例、白话解释、术语就地注解、最小改进、代价、什么时候不需要、复述题、至少三类练习，以及必要时放在正文末尾的图示或深入内容。

所有抽象都必须回答：

1. 当前哪一种变化或测试问题证明它有价值？
2. 新边界把变化限制在哪里？
3. 新增间接性是否比原问题更容易维护？

## 示例工程验收标准

- 支持 Node.js 22 LTS 及以上版本。
- 使用 npm、ESM、严格 TypeScript 与 Vitest。
- 外部 JSON 先作为 `unknown` 校验。
- 领域规则不 import HTTP、数据库或进程环境。
- 应用用例依赖窄的 `TaskRepository` 端口。
- 提供创建、查询、列出和完成任务的 HTTP 路由。
- 覆盖领域规则、应用协调与 HTTP 边界测试。
- `npm run typecheck`、`npm test` 和 `npm run build` 全部通过。

## 非目标

- 不实现身份认证、租户、消息队列或真实云部署。
- 不引入依赖注入容器、ORM、完整 Redux 应用或微服务集群。
- 不把模式数量、目录层数或类数量当作架构质量。
- 不声称搜索摘要等同于已逐段核验的官方原文。
