# 附录：术语表

这份表用于回查，不用于脱离问题背诵。每个词都应回到正文中的变化、失败或测试场景理解。

| 术语 | 人话解释 | 首次重点章节 |
| --- | --- | --- |
| 职责 Responsibility | 一组由同一所有者维护的知识和决定 | 第 1—2 章 |
| 依赖 Dependency | 完成工作前必须知道或使用什么 | 第 2 章 |
| 耦合 Coupling | 一处变化牵连另一处的程度 | 第 1—2 章 |
| 内聚 Cohesion | 放在一起的内容是否共同解决一类问题 | 第 2 章 |
| 运行时边界 | 外部未知值被检查并转成可信值的位置 | 第 3 章 |
| 契约 Contract | 调用双方共同依赖的输入、输出、错误与行为 | 第 4、7 章 |
| SRP | 一个模块主要对一类变化原因负责 | 第 5 章 |
| OCP | 新增已知变体时尽量少改稳定流程 | 第 6 章 |
| LSP | 一个实现替换另一个时不撤回行为承诺 | 第 7 章 |
| ISP | 调用者只依赖自己需要的协作面 | 第 7 章 |
| DIP | 重要策略定义需要的端口，技术细节来适配 | 第 8 章 |
| DI | 从外部提供依赖，不在内部偷偷创建或查找 | 第 8 章 |
| Adapter | 把不匹配的外部接口翻译成内部接口 | 第 8、11 章 |
| Repository | 为应用提供面向对象/聚合的持久化协作边界 | 第 8、21 章 |
| DRY | 同一条决定不要在多个地方分别维护 | 第 9 章 |
| KISS | 选择当前最容易正确理解和维护的方案 | 第 9 章 |
| YAGNI | 没有真实需求支撑的能力先不实现 | 第 9 章 |
| Factory | 集中已经复杂化的选择和创建规则 | 第 10 章 |
| Builder | 分步骤配置并最终构造复杂结果 | 第 10 章 |
| Facade | 为复杂子系统提供更高层、更窄入口 | 第 11 章 |
| Decorator | 保持原接口并叠加行为 | 第 11 章 |
| Command | 表达一次希望执行的意图和所需数据 | 第 12 章 |
| State | 集中状态允许的行为和迁移 | 第 12、17 章 |
| Observer | 变化后通知不必被发布者具体认识的接收者 | 第 12 章 |
| 状态所有权 | 谁能改变状态、谁读取、它活多久 | 第 14 章 |
| 六边形架构 | 核心通过端口与多个适配器协作 | 第 15 章 |
| Clean Architecture | 源码依赖指向更稳定的业务策略 | 第 15 章 |
| Entity | 由稳定身份延续的领域对象 | 第 16 章 |
| Value Object | 由属性值和不变量定义的对象 | 第 16 章 |
| Aggregate | 必须共同维护强一致性的边界 | 第 16 章 |
| Bounded Context | 一套领域语言和模型明确适用的范围 | 第 16 章 |
| Workflow | 有顺序、失败和恢复规则的多步骤过程 | 第 17 章 |
| Domain Event | 领域中已经发生的事实 | 第 17 章 |
| Integration Event | 跨上下文/进程发布的版本化事实契约 | 第 17 章 |
| Outbox | 在同一事务记录待发布事件的可靠模式 | 第 17、21 章 |
| 模块化单体 | 同一部署内保持真实业务模块边界 | 第 18 章 |
| 微服务 | 独立部署并拥有数据的业务服务 | 第 18 章 |
| 幂等 | 重复执行仍产生同一业务效果 | 第 20 章 |
| 补偿 | 用新业务动作抵消无法原子回滚的先前动作 | 第 20 章 |
| 乐观并发 | 更新时验证版本，防止静默覆盖 | 第 20—21 章 |
| Cursor pagination | 依据上一页最后排序键继续查询 | 第 21 章 |
| Log / Metric / Trace / Audit | 事件记录、整体数值、调用路径、责任事实 | 第 22 章 |
| Context engineering | 组织模型当前需要的规则、目标和证据 | 第 24 章 |
| Eval | 用固定任务集反复测量一类能力 | 第 25 章 |
